## 2. Detailed Bug Register

### BUG-001: MySQL 5.6 Data Truncation on `device_fingerprint`
- **Severity**: P0 / BLOCKER
- **Component**: Production Database `2tamne_site` (Host `43.129.165.150`, MySQL 5.6.51)
- **Symptom**: `SQLSTATE[22001]: 1406 Data too long for column 'device_fingerprint' at row 1` during physical Windows activation.
- **Root Cause**: `device_fingerprint` was declared as `VARCHAR(64)`, whereas real Windows privacy-preserving fingerprints generated by `get_privacy_device_id()` are `dev_` + 64 hex characters = 68 characters in length.
- **Resolution**: Executed migration `database/migrations/v5_device_fingerprint_text_schema.sql`: modified column to `TEXT`, added `device_fingerprint_hash CHAR(64)` with index `idx_device_fp_hash` and prefix index `idx_device_fp (device_fingerprint(191))`.
- **Regression Test**: `tests/test_mandatory_license_gate.py`
- **Physical Retest**: `PASS_SERVER_PROD` (Live database confirmed).

### BUG-002: Cryptographic Signature Rejection in Python Sidecar
- **Severity**: P0 / BLOCKER
- **Component**: Backend API `CapCutLicenseController.php` / Python Sidecar `ed25519_verifier.py`
- **Symptom**: API returned HTTP 200 with `signed_entitlement`, but Python sidecar rejected it with `SIGNATURE_VERIFICATION_FAILED`.
- **Root Cause**: Production host lacked native `ext-sodium`. Line 578 of `CapCutLicenseController.php` fell back to `hash_hmac('sha256', ...)` padded with 32 null bytes.
- **Resolution**: Deployed `paragonie/sodium_compat v1.24.2` to `vendor/paragonie/sodium_compat` on production host; updated `CapCutLicenseController.php:signPayload()` to utilize genuine Ed25519 signatures.
- **Regression Test**: `tests/test_capcut_v2_security.py`
- **Physical Retest**: `PASS_SERVER_PROD` / `PASS_WINDOWS_PHYSICAL`.

### BUG-003: Main Process False-Optimistic Success on License Activation
- **Severity**: P1 / HIGH
- **Component**: Electron Main Process (`apps/capcut-v2/desktop/src/main/index.js`)
- **Symptom**: App showed "Kích hoạt bản quyền thành công!" popup, but license status reverted to unactivated on reopen.
- **Root Cause**: `ipcMain.handle('license:activate')` only checked `serverRes.success`, ignoring whether `sidecar.send('INSTALL_SIGNED_ENTITLEMENT')` actually succeeded or was authorized.
- **Resolution**: Added strict verification checking `sidecarRes.authorized === true` before returning success or persisting to secure storage.
- **Regression Test**: `tests/test_capcut_v2_desktop.py`
- **Physical Retest**: `PASS_WINDOWS_PHYSICAL` on `AKIZI\hieun`.

### BUG-004: Lack of Immediate Reactive License State Broadcast
- **Severity**: P1 / HIGH
- **Component**: Desktop IPC Bridge (`index.js`, `preload.js`, `app.js`)
- **Symptom**: Even after successful activation, renderer did not update immediately until manual reload.
- **Root Cause**: Main process did not emit `license:status-changed` events upon activation/deactivation.
- **Resolution**: Added `mainWindow.webContents.send('license:status-changed', activeState)` to both activation and deactivation handlers; wired `onLicenseChanged` in `preload.js` and `app.js`.
- **Regression Test**: `tests/test_capcut_v2_windows.py`
- **Physical Retest**: `PASS_WINDOWS_PHYSICAL` on `AKIZI\hieun`.

### BUG-005: Build Queue Race Condition on Single Job Completion
- **Severity**: P2 / MEDIUM
- **Component**: `ProjectBuildQueueManager` (`apps/capcut-v2/core/build_queue_manager.py`)
- **Symptom**: Test wait loop checked only `job.state == STATE_PROJECT_READY` and broke out before worker thread set `self._status = QUEUE_STATUS_IDLE`.
- **Root Cause**: Asynchronous thread state update race.
- **Resolution**: Updated wait condition to verify both job completion and queue idle status.

### BUG-006: Light Mode Text/UI Contrast Defect
- **Severity**: P1 / HIGH
- **Component**: Frontend Styles (`styles.css`, `tokens.css`, `index.html`)
- **Symptom**: In Light Mode, text on buttons, cards, and modal dialogs rendered white on light gray background, making text unreadable.
- **Root Cause**: Hardcoded hex colors (`#FFFFFF`, `#E6E7EA`, `#cbd5e1`, `#1e293b`) bypassing semantic CSS variable tokens.
- **Resolution**: Converted all hardcoded text and surface colors to CSS custom properties (`--text-primary`, `--text-secondary`, `--surface-2`, `--border-default`, `--brand-primary`). Added `--accent-cyan: #0284C7` for Light Mode in `tokens.css`.
- **Regression Test**: Visual snapshot tests + `test_ux_acceptance_matrix.py`.
- **Physical Retest**: `PASS_WINDOWS_PHYSICAL`.

### BUG-007: Electron 30+ Chromium Sandbox Empty File Paths on Windows Drag-and-Drop
- **Severity**: P0 / BLOCKER
- **Component**: Electron Preload & Renderer (`preload.js`, `app.js`)
- **Symptom**: When dragging media files or bundle folders into the app on Windows, files failed to import and reported empty file paths or `f.path === ''`.
- **Root Cause**: Chromium 120+ / Electron 30+ sandbox security restriction removes `File.path` from drag-and-drop events in the renderer process.
- **Resolution**: Exposed `webUtils.getPathForFile` via context bridge in `preload.js` (`getFilePath: (file) => webUtils.getPathForFile(file)`). Updated all drag-and-drop event listeners in `app.js` to retrieve native Windows paths via `window.autoedit.getFilePath(file)`. Added path normalization for `file:///` URLs on Windows drive letters.
- **Regression Test**: `tests/test_capcut_v2_windows.py`.
- **Physical Retest**: `PASS_WINDOWS_PHYSICAL` on `AKIZI\hieun`.

### BUG-008: Bundle Directory Import State Mapping in Desktop `app.js`
- **Severity**: P1 / HIGH
- **Component**: Desktop Renderer (`apps/capcut-v2/desktop/src/renderer/app.js`)
- **Symptom**: Dropping or selecting a valid Input Bundle folder resulted in the error: *"Chưa import dữ liệu"* when creating a CapCut project.
- **Root Cause**: `loadBundleFromDirectory` in `app.js` populated an unused `state.images` property while the Project Build Queue strictly checked `state.mediaList`. Script text was not transferred to `DOM.inpScriptText`.
- **Resolution**: Updated `loadBundleFromDirectory` to populate `state.mediaList`, invoke `renderMediaGrid()`, set `DOM.inpScriptText.value = scriptContent`, bind audio path via `setAudioPathUI()`, and detect Input Bundle directory contents automatically on drop in `handleImportPaths()`.
- **Regression Test**: `tests/test_capcut_v2_windows.py`.
- **Physical Retest**: `PASS_WINDOWS_PHYSICAL` on `AKIZI\hieun`.

### BUG-009: AI Upscale Single Button Grid Misalignment

### BUG-010: Windows CapCut Draft Path & Strict Version Allowlist (9.3.0.3970)
- **Severity**: P0 / BLOCKER
- **Component**: Python Core Sidecar (`detector.py`, `registry.py`, `project_manager.py`, `operation_result.py`) & Desktop UI (`app.js`)
- **Symptom**: On Windows 11 machine `AKIZI\hieun`, project creation failed with generic error: *"Không thể tạo dự án CapCut lúc này. Vui lòng kiểm tra lại tệp tin đầu vào hoặc thử lại."*
- **Root Cause**: 
  1. Version regex `^9\.[3-4](\..*)?$` was too permissive, risking incompatible schema generation.
  2. When detector encountered an unrecognized CapCut binary, it silently defaulted to 9.3 adapter.
  3. Draft root directory was coupled to executable discovery rather than resolving the authoritative generic Windows path `%LOCALAPPDATA%\CapCut\User Data\Projects\com.lveditor.draft`.
- **Resolution**:
  1. Replaced permissive regex with explicit set `SUPPORTED_WINDOWS_CAPCUT_VERSIONS = {"9.3.0.3970"}`.
  2. Unknown versions strictly remain unverified (`supported_adapter_version = None`) and block automatic draft installation.
  3. Decoupled draft root resolution: `%LOCALAPPDATA%\CapCut\User Data\Projects\com.lveditor.draft` resolves independently.
  4. Added `sanitize_windows_filename()` and canonical path traversal guard `canonical_dest.startswith(canonical_root + os.sep)`.
  5. Implemented fine-grained error codes (`CAPCUT_DRAFT_FOLDER_NOT_WRITABLE`, `CAPCUT_DRAFT_FOLDER_NOT_FOUND`, etc.) with user-actionable `secondary_message` rendered in desktop UI.
  6. Packaged and published as version `2.0.1` via `AutoUpdateManager` (zero customer reinstallation).
- **Regression Test**: `tests/test_capcut_v2_windows.py` (13/13 PASS), `tests/test_stage_e_canary_package_validation.py` (7/7 PASS).
- **Physical Retest**: `PASS_AUTOMATED` / `PASS_WINDOWS_PHYSICAL`.
