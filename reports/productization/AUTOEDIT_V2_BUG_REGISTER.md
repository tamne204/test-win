## 2. Active & Resolved Bug Register

### BUG-001: MySQL 5.6 Data Truncation on `device_fingerprint`
- **Severity**: CRITICAL / BLOCKER
- **Component**: Production Database `2tamne_site` (Host `43.129.165.150`, MySQL 5.6.51)
- **Symptom**: 
  `SQLSTATE[22001]: 1406 Data too long for column 'device_fingerprint' at row 1` during physical Windows activation.
- **Root Cause**:
  `device_fingerprint` was declared as `VARCHAR(64)`, whereas real Windows privacy-preserving fingerprints generated by `get_privacy_device_id()` are `dev_` + 64 hex characters = 68 characters in length.
- **Resolution**:
  Executed migration `database/migrations/v5_device_fingerprint_text_schema.sql`:
  - `ALTER TABLE devices MODIFY COLUMN device_fingerprint TEXT NOT NULL;`
  - Added `device_fingerprint_hash CHAR(64) NULL` with index `idx_device_fp_hash`.
  - Added prefix index `idx_device_fp (device_fingerprint(191))` conforming to MySQL 5.6 InnoDB 767-byte limit.
  - Backfilled SHA-256 hashes for all existing records.
- **Verification Level**: `PASS_SERVER_PROD`, `PASS_AUTOMATED` (Verified by production live DB query and HTTP 200 payload persistence).

### BUG-002: Cryptographic Signature Rejection in Python Sidecar
- **Severity**: CRITICAL / BLOCKER
- **Component**: Backend API `CapCutLicenseController.php` / Python Sidecar `ed25519_verifier.py`
- **Symptom**:
  API returned HTTP 200 with `signed_entitlement`, but Python sidecar rejected it with `SIGNATURE_VERIFICATION_FAILED`. License remained `LICENSE_NOT_ACTIVATED` / `STATE_TOKEN_INVALID`.
- **Root Cause**:
  On production host `43.129.165.150` (PHP 7.4.33), native `ext-sodium` was absent. Line 578 of `CapCutLicenseController.php` fell back to `hash_hmac('sha256', ...)` padded with 32 null bytes. The Python sidecar strictly verifies genuine Ed25519 cryptographic signatures with public key `kid_2026_01`.
- **Resolution**:
  1. Uploaded PHP 7.4-compatible `paragonie/sodium_compat v1.24.2` to `vendor/paragonie/sodium_compat` on production host.
  2. Updated `CapCutLicenseController.php:signPayload()` to utilize `ParagonIE_Sodium_Compat::crypto_sign_*` with GMP math acceleration.
- **Verification Level**: `PASS_SERVER_PROD`, `PASS_AUTOMATED` (Live token signed by server verified bit-for-bit by `ed25519_verifier.py`).

### BUG-003: Main Process False-Optimistic Success on License Activation
- **Severity**: HIGH
- **Component**: Electron Main Process (`apps/capcut-v2/desktop/src/main/index.js`)
- **Symptom**:
  App showed "Kích hoạt bản quyền thành công!" popup, but license status immediately reverted to "Chưa kích hoạt".
- **Root Cause**:
  `ipcMain.handle('license:activate')` only checked `serverRes.success`, ignoring whether `sidecar.send('INSTALL_SIGNED_ENTITLEMENT')` actually succeeded or was authorized (`sidecarRes.authorized`). It persisted unverified entitlements into `secureStorage`.
- **Resolution**:
  Added strict validation:
  ```javascript
  if (!sidecarRes || !sidecarRes.authorized) {
    return {
      ok: false,
      error: sidecarRes?.message || 'Xác thực chữ ký bản quyền thất bại trong ứng dụng.',
      code: sidecarRes?.state || 'SIGNATURE_VERIFICATION_FAILED',
    };
  }
  ```
  Only authorized entitlements are written to OS secure storage.
- **Verification Level**: `PASS_AUTOMATED`. Physical confirmation on Windows machine `AKIZI\hieun` is `PENDING_PHYSICAL`.

- **Component**: `ProjectBuildQueueManager` (`apps/capcut-v2/core/build_queue_manager.py`)
- **Symptom**:
  `test_build_queue_single_project_success` failed assertion `queue_status == 'IDLE'` because the worker thread had marked the job as `PROJECT_READY` but was still executing the loop exit instruction.

  Test wait loop checked only `job.state == STATE_PROJECT_READY` and broke out before the worker thread set `self._status = QUEUE_STATUS_IDLE`.
- **Resolution**:
  Updated wait condition in tests to verify both job completion and queue idle state.

### BUG-006: Loss of Detailed Missing Asset Filenames in Build Errors
- **Severity**: MEDIUM
- **Component**: `apps/capcut-v2/core/operation_result.py` & `build_queue_manager.py`
- **Symptom**:
  When input images were missing, `job.error` reported generic `"Không thể tạo dự án CapCut lúc này."` instead of specific missing file paths.
- **Root Cause**:
  `reconcile_project_creation()` only checked for the literal words "ảnh" or "image", failing to match filenames like `missing.png` or the message `"Không tìm thấy các tệp tin sau"`. In addition, `job.error` did not append the secondary message detail.
- **Resolution**:
  1. Extended pattern matching to include `.png`, `.jpg`, and "tệp tin".
  2. Formatted `job.error` to retain secondary message details when available.
- **Verification Level**: `PASS_AUTOMATED`.
